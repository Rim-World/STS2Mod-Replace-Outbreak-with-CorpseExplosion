# v0.113.0 失效评估：死亡钩子签名变化导致尸爆不触发

- 日期：2026-11-13（初版同日修正）
- 评估对象：本 mod v1.0.0（`min_game_version` 0.110.0）
- 评估方式：静态比对 v0.107 / v0.111 / v0.113 反编译源码与 mod 源码；最小 .NET 复现实验；只读，未构建、未实机
- 结论：**核心机制失效**，主因不是伤害重载，而是死亡钩子签名变化：
  1. v0.113 的 `AbstractModel.AfterDeath` 新增 `CardModel? source` 参数，mod 按 0.111 编译的 4 参 `override` 不再构成重写，钩子**根本不会被调用**，爆炸不触发、也不报错。
  2. `CreatureCmd.Damage` 多目标重载由 7 参变 8 参；即使钩子被修好，按 7 个类型查找仍返回 `null`，随后 `null` 解引用。

## 修正说明

初版报告把 `Damage` 反射列为直接原因，并推断触发时抛 `NullReferenceException`。复核发现：钩子不会执行，`ApplyDamage` 永远不会被调用，因此 0.113 上既不爆炸也不报错。`Damage` 是修好钩子之后必须同步修的第二个问题。

## 机制判定

- .NET 加载「基类方法签名已变化」的旧 override 不会抛 `TypeLoadException`：最小复现实验中类型正常加载，虚调用走基类实现。
- 因此 `PowerCmd.Apply<CorpseExplosionPower>`、毒伤、Buff 图标都正常；只有死亡时的爆炸分支静默丢失。

## 影响

- 卡牌本身可以打出：「爆发」的 `OnPlay`、费用、文本、卡图补丁的目标均未变。
- 目标死亡时：没有任何爆炸伤害，也没有异常日志。玩家看到的现象是「尸爆标记不生效」。
- 不会连带中断死亡结算。

## 修复方向

1. 删除 `CorpseExplosionPower` 的 `AfterDeath` override，改为对 `AbstractModel.AfterDeath` 挂 Harmony Prefix，按名取三版本共有的参数，命中本 Power 时提供 `Task` 结果。
2. `Damage` 统一走三版本都存在的 5 参重载 `(ctx, IEnumerable<Creature>, decimal, ValueProp, Creature)`：它逐级转发到当前版本的最终实现，`cardSource` / `cardPlay` 为 `null`，无需处理 `ModifyDamageHookType` 或可选参数。
3. 详细步骤、改动清单与验收见 `2.PLANS/003-S-Damage重载三版本兼容修复.md`。

## 验证状态

- 已验证：三版本签名差异（反编译行号）；孤立 override 的运行行为（最小 .NET 9 实验）；Harmony Prefix 在 4 参 / 5 参目标上的按名绑定（同一实验）；5 参 `Damage` 在 0.107 / 0.111 / 0.113 均存在且转发链一致。
- 补充：manifest 允许 0.110，0.110 的 `Outbreak` 形状、4 参 `AfterDeath`、7 参 `Damage` 均与本方案兼容。
- 未验证：修正后的实机效果（未构建、未运行）。


## 修复结果（2026-11-13）

- 已删除按 0.111 四参签名声明的 `CorpseExplosionPower.AfterDeath` override，改用 `AbstractModel.AfterDeath` 的 Harmony Prefix；0.113 五参目标与 0.111 四参目标均按参数名绑定。
- `CreatureCmd.Damage` 已收敛为三版本共有的 5 参多目标重载，删除 7 参 / 6 参分支；解析失败或执行异常时记录错误并跳过本次伤害。
- manifest 版本 `1.0.0` → `1.0.1`，`min_game_version` 维持 `0.110.0`。
- 已构建并覆盖安装到本地 `mods/CorpseExplosionReplacementMod`；0.113 启动日志出现 `AbstractModel.AfterDeath hook applied`，无异常。实机击杀触发待用户验收。

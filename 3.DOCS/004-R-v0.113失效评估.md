# v0.113.0 失效评估：`CreatureCmd.Damage` 重载变化导致尸爆无伤害

- 日期：2026-11-13
- 评估对象：本 mod v1.0.0（`min_game_version` 0.110.0）
- 评估方式：静态比对 v0.111 / v0.113 反编译源码与 mod 源码；只读，未构建、未实机
- 结论：**核心机制失效**。v0.113 给 `CreatureCmd.Damage` 的 7 参重载追加了第 8 个可选参数，mod 按 7 个参数类型取 `MethodInfo` 得到 `null`，触发尸爆时对 `null` 解引用。

## 证据

| 位置 | 内容 |
|---|---|
| `STS2-Reference/2.STS2-111Reference/decompiled/MegaCrit.Sts2.Core.Commands/CreatureCmd.cs:258` | v0.111：`Damage(ctx, IEnumerable<Creature>?, decimal, ValueProp, Creature?, CardModel?, CardPlay?)`，7 参 |
| `STS2-Reference/3.STS2-113Reference/decompiled/MegaCrit.Sts2.Core.Commands/CreatureCmd.cs:263` | v0.113：同前 7 参 + `ModifyDamageHookType modifyDamageHookType = ModifyDamageHookType.All`，实际 8 参 |
| `STS2-Reference/3.STS2-113Reference/decompiled/MegaCrit.Sts2.Core.Commands/CreatureCmd.cs:285` | v0.113 另有 8 参 `IEnumerable<DamageTargetData>?` 版本 |
| `9.SRC/CorpseExplosionReplacementMod/CorpseExplosionPower.cs:31` | 按 7 个具体类型查找 `Damage` |
| `9.SRC/CorpseExplosionReplacementMod/CorpseExplosionPower.cs:37` | 回退分支按 6 个具体类型查找 `Damage` |
| `9.SRC/CorpseExplosionReplacementMod/CorpseExplosionPower.cs:94` | 两个查找都为 `null` 时执行 `DamageSixArg!.Invoke(...)` |

`Type.GetMethod(name, Type[])` 精确匹配参数个数。可选参数在反射里仍是形参，所以 7 个类型匹配不到 8 个形参的方法。

v0.113 中也不存在 `(PlayerChoiceContext, IEnumerable<Creature>, decimal, ValueProp, Creature, CardModel)` 这个 6 参版本：带 `CardModel` 但无 `CardPlay` 的重载从未存在。因此两个 `MethodInfo` 都是 `null`。

## 影响

- 卡牌本身可以打出：「爆发」的 `OnPlay`、费用、文本、卡图补丁的目标均未变。
- 触发尸爆时：`AfterDeath` 钩子进入 `ApplyDamage`，`DamageSixArg!` 为 `null`，抛 `NullReferenceException`。
- 后果：爆炸伤害不结算，标记失去意义。异常发生在敌方死亡结算链路中，是否连带影响该次死亡事件的其余结算，未实机验证。

## 修复方向

1. 反射签名改为包含第 8 个参数 `ModifyDamageHookType`，`Invoke` 时显式传值（可选参数在 `Invoke` 中必须补位）。
2. 或改按 5 参 `Damage(ctx, IEnumerable<Creature>, decimal, ValueProp, Creature)` 调用，再单独处理卡源；语义需确认。
3. 两条查找失败时应记录错误并跳过，不要对 `null` 解引用。

未验证：只有静态源码比对，没有构建，也没有在 v0.113 实机运行。

# 0.111.1 与 0.113.1 兼容性检查报告

- 日期：2026-11-18
- 检查对象：`CorpseExplosionReplacementMod` v1.0.1 → v1.1.0
- 检查范围：`0.111.1`（正式版）与 `0.113.1`（beta）的 `sts2.dll` 公共 API、mod 补丁目标、加载与运行行为
- 检查方式：反编译比对、程序集元数据、双版本编译、0.113.1 无头启动与场景测试
- 结论：**发现 1 处需要新增兼容处理**（0.113.1 的 `CardModel.BigPortrait` / `NCard.SetPortraitTexture` 图鉴大图路径）；其余现有补丁目标在两版本均存在且签名兼容。已新增条件补丁，未发现会导致启动崩溃或补丁整体失效的其他差异。

## 2. 关键 API 差异

### 2.1 死亡钩子

| 成员 | 0.111.1 | 0.113.1 |
|---|---|---|
| `AbstractModel.AfterDeath` | `(PlayerChoiceContext, Creature, bool, float)` | `(PlayerChoiceContext, Creature, CardModel?, bool, float)` |
| `Hook.AfterDeath` | 4 参分发 | 5 参分发，多传 `source` |

证据：

- 0.111.1：`TMP/1.1.0/ref-111.1/MegaCrit.Sts2.Core.Models.AbstractModel.cs:316`
- 0.113.1：`4.STS2-113.1Reference/decompiled/MegaCrit.Sts2.Core.Models/AbstractModel.cs:709`
- 0.111.1：`TMP/1.1.0/ref-111.1/MegaCrit.Sts2.Core.Hooks.Hook.cs:333`
- 0.113.1：`4.STS2-113.1Reference/decompiled/MegaCrit.Sts2.Core.Hooks/Hook.cs:501`

判定：现有 `CorpseExplosionDeathHookPatch` 只声明 `choiceContext`、`creature`、`wasRemovalPrevented` 与 `__instance`、`__result`，Harmony 按参数名绑定，四参与五参目标都能命中。**无需改动**。

### 2.2 `CreatureCmd.Damage`

| 版本 | 5 参多目标重载 | 转发链 |
|---|---|---|
| 0.111.1 | `(ctx, IEnumerable<Creature>, decimal, ValueProp, Creature)`，第 99 行 | 转发到 7 参 |
| 0.113.1 | 同签名，第 148 行 | 转发到 7 参，再转发到 8 参（`ModifyDamageHookType` 默认 `All`） |

证据：

- 0.111.1：`TMP/1.1.0/ref-111.1/MegaCrit.Sts2.Core.Commands.CreatureCmd.cs:99`
- 0.113.1：`4.STS2-113.1Reference/decompiled/MegaCrit.Sts2.Core.Commands/CreatureCmd.cs:148`
- 0.113.1 的 8 参重载：同文件 `:263`、`:285`

判定：mod 只查 5 参重载，两版本都存在；`dealer` 参数运行时类型都是 `Creature`，反射传 `null` 可行。**无需改动**。

### 2.3 `Outbreak`

两版本的 `Outbreak` 均为：

- 构造器 `base(3, CardType.Skill, CardRarity.Rare, TargetType.AllEnemies)`。
- `ExtraHoverTips` 为 `PoisonPower`。
- `CanonicalVars` 为 `PoisonPower(9m)`。
- `OnPlay` 对全体施毒并立即触发。
- `OnUpgrade` 对毒加 3。

证据：

- 0.111.1：`TMP/1.1.0/ref-111.1/MegaCrit.Sts2.Core.Models.Cards.Outbreak.cs:18-51`
- 0.113.1：`4.STS2-113.1Reference/decompiled/MegaCrit.Sts2.Core.Models.Cards/Outbreak.cs:18-51`

判定：形态守卫（Skill / AllEnemies / 3 费）在两版本都通过。**无需改动**。

### 2.4 图鉴大图与 `BigPortrait`（本轮唯一需要新增处理的地方）

| 成员 | 0.111.1 | 0.113.1 |
|---|---|---|
| `CardModel.BigPortrait` | 不存在 | 存在，`CardModel.cs:185` |
| `NInspectCardScreen.UpdateCardDisplay` | 只 `UpdateVisuals`，`NInspectCardScreen.cs:282` | 额外 `_card.SetPortraitTexture(cardModel2.BigPortrait)`，`:372`、`:395` |
| `NCard.SetPortraitTexture` | 不存在 | 存在，`NCard.cs:1305` |
| `NInspectCardScreen.SetCard` | 私有，`:309` | 私有，`:400`，方法体与 0.111.1 相同 |

0.113.1 的 `UpdateCardDisplay` 在正常路径下会把卡图替换为 `BigPortrait`。`BigPortrait` 的实现是：

```csharp
if (!HasPortrait) return Portrait;
return PreloadManager.Cache.GetTexture2D(PortraitPngPath);
```

本 mod 已把 `PortraitPngPath` 指到 mod PCK 内的 PNG。`BigPortrait` 因此会走 `PreloadManager.Cache`，而该缓存会把非 `AtlasTexture` 记为 `_missedCacheAssets`，在回主菜单等边界被 `UnloadMissedCacheAssets` Dispose。下一次打开图鉴时，如果 `GetAsset` 返回失效实例或 `SetPortraitTexture` 抛异常，就会退回 `OutbreakInspectCardGuardPatch` 的兜底渲染（卡牌可见，但日志出现告警、hover tips 被跳过）。

判定：需要新增一个只在 0.113.1 存在的 `CardModel.BigPortrait` 条件补丁，把 `Outbreak` 的 `BigPortrait` 接到 `PortraitTextureLoader`。该补丁不能放进 `PatchAll`，否则 0.111.1 上会因属性缺失抛 `HarmonyException`。

### 2.6 行为语义差异

0.113.1 的 `PowerCmd.Apply` 把 `SkipNextDurationTick` 的条件收紧为「目标是玩家、当前是敌人回合、Power 是 Debuff」。本 mod 在玩家回合给敌人施加 Debuff，不进入该分支，**无影响**。

## 3. 本地化

mod 提供 15 种语言：`deu`、`eng`、`esp`、`fra`、`ita`、`jpn`、`kor`、`pol`、`ptb`、`rus`、`spa`、`tha`、`tur`、`zhs`、`zht`。

游戏语言差异：

- 0.111.1 有 `ind`，无 `ara`。
- 0.113.1 有 `ind` 与 `ara`。

mod 没有 `ind` 与 `ara` 文件。游戏按语言加载 mod 本地化，缺文件时回退英文；不会阻止启动。**未验证**：实际把游戏语言切到 `ind` / `ara` 后的文本显示。确认方法：切换语言后打开图鉴与战斗，检查卡名/描述是否为英文而非空键。

## 6. 0.113.1 场景测试

测试工件：

- `8.TEST/1.1.0/CorpseExplosionProbe/`：注册 `ce_probe` 与 `ce_check`，打印 Outbreak 属性与战斗生物血量/Power，并断言战斗状态；同时解除发行版的 `--scenario` 限制。
- `8.TEST/1.1.0/corpse-explosion-compat.scenario`：进入 `CORPSE_SLUGS_NORMAL`（3 只 Corpse Slug），给第一只挂 `CORPSE_EXPLOSION_POWER` 1 层，杀死第一只，等待 3 秒后再次探测。
- `8.TEST/1.1.0/corpse-explosion-lethal.scenario`：同上，但挂 2 层，并用 `ce_check combat-ended` 断言战斗结束。

### 6.1 1 层测试（`TMP/1.1.0/test-logs/0.113.1-20261118-191748.engine.log`；脱敏摘录 `8.TEST/1.1.0/logs/0.113.1-compat-evidence.log`）

初始状态：

| 生物 | HP |
|---|---|
| 铁甲战士 | 80/80 |
| 噬尸蛞蝓 1（被击杀） | 25/25 |
| 噬尸蛞蝓 2 | 26/26 |
| 噬尸蛞蝓 3 | 27/27 |

击杀 25 点最大生命的蛞蝓 1 后，存活敌人变为：

| 生物 | HP | 损失 |
|---|---|---|
| 噬尸蛞蝓 2 | 1/26 | 25 |
| 噬尸蛞蝓 3 | 2/27 | 25 |

两只存活敌人各损失 25 点，等于被击杀者的最大生命值 × 1，且不等于各自最大生命值。这排除了「只扣 1 点」「按各自最大生命值结算」「完全未触发」三种错误实现。

### 6.2 2 层测试（`TMP/1.1.0/test-logs/0.113.1-20261118-192930.engine.log`；脱敏摘录 `8.TEST/1.1.0/logs/0.113.1-compat-evidence.log`）

挂 2 层后击杀 25 点最大生命的蛞蝓 1，剩余两只被 50 点伤害杀死，`ce_probe` 输出 `combat=not-in-progress`，`ce_check combat-ended` 通过，场景以 exit code 0 结束。同一轮 `ce_probe` 还读取 `Outbreak.BigPortrait`，结果为 `valid=True type=CompressedTexture2D`，说明 0.113.1 的 `BigPortrait` 已接到有效纹理。

### 6.3 日志中的非问题项

- `Localization formatting error ... selector named "PoisonPower"` 是探针在无卡牌变量上下文调用 `GetFormattedText()` 造成的；最终探针已改用 `GetRawText()`，最后一轮日志不再出现该错误。它不是 mod 运行时错误。
- 退出时的 `RID allocations were leaked` 与 `resources still in use` 是 Godot 无头退出常见提示，与 mod 无关。

## 7. 结论与后续

1. 0.113.1 与 0.111.1 的兼容差异集中在图鉴大图；死亡钩子与伤害重载的现有修复仍然成立。
2. 新增 `BigPortrait` 条件补丁后，单份 DLL 可以继续覆盖两个版本。
3. `min_game_version` 收紧到 `0.111.1`，0.111.0 及更旧版本由游戏拒绝加载。
4. 0.113.1 的死亡爆炸已通过探针场景验证；0.111.1 只完成编译检查，需要用户实机回归（打出、爆炸、图鉴大图、Buff 图标、主菜单往返）。
5. 0.114+ 不在承诺范围；游戏更新后按本报告第 2 节的表逐项复查。

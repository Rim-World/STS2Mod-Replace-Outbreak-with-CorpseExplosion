# 调研笔记：110→107 切换导致“存档无法读取、只能放弃”的根因（2026-08-10）

## 结论

这不是五个自写 mod 写入非法存档数据导致的损坏，而是 **STS2 游戏本身不允许用旧版本读取新版本的 run 存档**：

- v0.110.1 的 `current_run.save` 为 `schema_version = 20`。
- v0.107.1 只支持到 `schema_version = 16`。
- 107 的 `MigrationManager` 发现“存档版本比当前版本新”后，对 `SerializableRun` 不做数据回收（该类型被明确排除），
  直接把 `current_run.save` 与 `.backup` 改名为 `*.FUT.corrupt`，随后主菜单显示存档无法读取。

五个 mod 中唯一引入自定义模型的尸爆术 `CorpseExplosionPower` 也不会进入 run 存档：
单机 run 存档只保存角色/牌组/遗物/药水/地图/进度等，不保存战斗中的 Power 实例；
抽查损坏存档 JSON 也未发现任何 `corpse_explosion_power` 或 mod 专属持久化字段。

## 证据

### 1. 110 会话（2026-08-10 22:51，日志 `godot2026-08-10T22.51.19.log`）

- `Release Version: v0.110.1`
- `Current save versions: ... SerializableRun v20; ...`
- 加载 36 个 mod，包含：
  - 自写五个：Recycle/Evolve/CorpseExplosion/Reaper/PhantomKiller；
  - 其他大量第三方 mod：BaseLib、Loadout、RegentFX、RitsuLib、CustomCardBalance、
    CustomAscensionBalance、Rewind、BetterMap、BetterConsole 等。
- 该会话写出了 `schema_version = 20` 的 run 存档。

### 2. 107 会话（2026-08-10 22:58，日志 `godot2026-08-10T22.58.02.log`）

- `Release Version: v0.107.1`
- `Current save versions: ... SerializableRun v16; ...`
- 加载 33 个 mod，其中同样包含大量第三方 mod 与 Recycle/Evolve 两个自写 mod。
- 关键日志原文：

```
[WARN] Save version 20 is newer than current 16, attempting recovery...
[ERROR] Save file version 20 is newer than current version 16: modded/profile2\saves\current_run.save
[ERROR] Corrupt save detected (FutureVersion): Renamed 'modded/profile2\saves\current_run.save' to
        'modded/profile2\saves\current_run.1786373524.FUT.corrupt'
[ERROR] Failed to load run save: status=FutureVersion msg=Save file version 20 is newer than current version 16
```

### 3. 用户数据目录中的 `.FUT.corrupt` 存档

实际盘点 `%APPDATA%\SlayTheSpire2\steam\76561198869461680\modded\profile2|3\saves`：

- 所有 `*.FUT.corrupt` 文件：`schema_version = 20`；
- 当前 107 能正常读取的 `current_run.save`：`schema_version = 16`；
- 抽查一份损坏存档：牌组含 `CARD.SCAVENGE` 等普通卡，`props` 只有原版字段（如 `TimesUsed`），
  没有任何 `CorpseExplosionPower` / `RE_` mod 自定义键。

## 为什么“看起来”只有自写 mod 触发

107 与 110 共用同一个 modded 存档路径：

`%APPDATA%\SlayTheSpire2\steam\<SteamID>\modded\profile<N>\saves\current_run.save`

因此只要 110 里留着一局未结束的 run，切到 107 后无论加载哪些 mod，游戏都会先看到 v20 存档并判为损坏。
此前感觉“其他 mod 不触发”，更可能是其他 mod 组合没有在 110 中留下未结束 run，或切换时机不同；
本次日志里 110 和 107 两个会话都同时加载了大量第三方 mod，说明触发条件是版本而非自写 mod。

## 初步方案

### A. 操作层面（推荐，零代码）

1. 从 110 降回 107 前，先在 110 里打完或放弃当前 run；
2. 或手动备份/恢复 modded 存档目录，例如切换前把
   `steam\76561198869461680\modded\profile<N>\saves` 复制为 `saves_110_backup`，
   切回 110 时再还原；
3. 用户数据目录里已有的 `- 副本`、`- （上传mod回107版本）` 文件夹正是这个思路，可以继续沿用。

### B. 版本隔离（需要一点脚本，不碰游戏代码）

维护两套完整的 `%APPDATA%\SlayTheSpire2\steam\<SteamID>` 目录（或只隔离 `modded` 子目录），
启动 107/110 前用脚本切换。Godot 4.5.1 命令行帮助里未看到 `--user-data-dir` 类参数，因此大概率要
靠文件目录切换或符号链接实现。

### C. 反向迁移工具（可选，需要写独立脚本/程序）

把 v20 run 存档反向转换为 v16：`CARD.SIDESTEP→CARD.SCARE`、
RNG 新格式→旧 counter、Battleworn Dummy V1/V2/V3→旧 encounter、LastingCandy 属性名改回，
并把 `schema_version` 改为 16。RNG 部分需要额外确认 `MegaRandom` 状态转换，不能保证 100% 无损；
实施前必须先对 `.FUT.corrupt` 副本做实验。

### D. Mod 侧防误伤（仅防数据丢失，不能跨版本续玩）

可在自写 mod 启动早期检查 `current_run.save` 的 `schema_version`，若高于当前游戏版本则先移动到
`saves/v110_backup/`，避免 107 将其改名 `.corrupt`；切回 110 时再还原。这是保护性 workaround，
不是让 107 读取 110 存档的解决方案。

## 待用户确认

- 是否需要找回已有的 `.FUT.corrupt` 存档（目前可恢复的代价是“降级转档”，不是原样继续 110 进度）；
- 希望采用 A/B/C/D 中的哪个方向；
- 后续如需实施 C/D，需要用户允许写独立脚本或 mod 代码，并允许在副本存档上验证。

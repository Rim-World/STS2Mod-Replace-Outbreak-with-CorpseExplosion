# ADR-002：兼容基线定为 0.111.1 与 0.113.1，并用条件补丁吸收版本差异

- 状态：已接受
- 日期：2026-11-18
- 项目版本：`1.1.0`
- 相关文件：`9.SRC/CorpseExplosionReplacementMod/ModEntry.cs`、`Patches/CorpseExplosionDeathHookPatch.cs`、`Patches/OutbreakBigPortraitPatch.cs`、`CorpseExplosionReplacementMod.json`

## 背景

2026-11-18 的游戏状态：

- beta 分支为 `0.113.1`，正式版为 `0.111.1`。
- 用户明确要求只兼容这两个版本。
- 0.113.1 的 `AbstractModel.AfterDeath` 为五参（新增 `CardModel? source`），0.111.1 为四参。
- 0.113.1 新增 `CardModel.BigPortrait`，并把 `NInspectCardScreen.UpdateCardDisplay` 改为调用 `_card.SetPortraitTexture(cardModel2.BigPortrait)`；0.111.1 没有这两个成员。
- 两版本的 `Outbreak` 形态相同，均为 Skill / AllEnemies / 3 费。
- 两版本的 `CreatureCmd.Damage` 都存在 5 参多目标重载。
- 两个 `sts2.dll` 的程序集版本均为 `0.1.0.0`，未强命名；`0Harmony.dll` 为 2.4.2，未强命名。

## 决策

发布一份 DLL 与一份 PCK，`min_game_version` 设为 `0.111.1`，在运行时探测并条件应用只在 0.113.1 存在的补丁；死亡钩子统一用按参数名绑定的 Harmony Prefix。

具体规则：

1. 死亡钩子不再写 `AfterDeath` override，改用 `[HarmonyPatch(typeof(AbstractModel), "AfterDeath")]` 的 Prefix，只声明两版本共有的参数名：`choiceContext`、`creature`、`wasRemovalPrevented`。
2. `CardModel.BigPortrait` 补丁不放进 `PatchAll`。`ModEntry` 先用 `AccessTools.PropertyGetter` 探测属性，存在才手动 `Harmony.Patch`。
3. 伤害统一调用两版本共有的 5 参 `CreatureCmd.Damage` 重载，不直接引用 0.113.1 的 8 参签名。
4. `min_game_version` 从 `0.110.0` 收紧到 `0.111.1`；低于该版本的客户端由游戏拒绝加载。
5. 不支持 `0.111.0` 及更旧版本；不承诺 `0.114` 及更高版本。

## 备选方案

| 方案 | 否决理由 |
|---|---|
| 为 0.111.1 与 0.113.1 各发布一份 DLL | 产生两个构建、两份发布资产与两套验收记录；用户明确只需兼容两个版本，单一 DLL 的维护成本更低 |
| 保留 `min_game_version = 0.110.0` | 0.110.x 与 0.111.0 未纳入本轮验收，继续声明允许会扩大未验证的兼容面 |
| 直接引用 `CardModel.BigPortrait` 并放进 `PatchAll` | 0.111.1 没有该属性，`PatchAll` 会因目标缺失抛 `HarmonyException`，并可能中断后续补丁 |
| 继续用四参 `AfterDeath` override | 0.113.1 上不会构成重写，钩子静默失效；已有 v1.0.1 的失效评估证据 |
| 按版本号分支加载两套代码 | 需要版本解析与两套二进制；本轮差异只有两处，条件探测更简单 |

## 后果

**获益**

- 一份构建覆盖正式版与 beta，发布与回滚简单。
- 0.111.1 上不会因为缺少 `BigPortrait` 导致补丁整体失败。
- 0.113.1 上图鉴大图继续走 mod 的安全纹理加载器，不受资源清理影响。

**代价**

- 0.111.0 及更旧版本被 manifest 拒绝；需要这些版本的玩家必须升级游戏。
- 0.114 及更高版本不保证可用；游戏再改 `AfterDeath`、`BigPortrait` 或 `NInspectCardScreen` 时需要重新检查。
- 条件补丁的探测逻辑增加了一处运行时分派，但只在启动时执行一次。

**下游必须遵守的规则**

- 新增只在单一版本存在的成员时，必须使用运行时探测或条件补丁，不得直接放进 `PatchAll`。
- 任何补丁目标变化都必须同时检查 0.111.1 与 0.113.1 的程序集。
- `6.SPEC/001-总体规范.md` 的 SP-003、SP-006、SP-013、SP-018 必须与本决策保持一致。

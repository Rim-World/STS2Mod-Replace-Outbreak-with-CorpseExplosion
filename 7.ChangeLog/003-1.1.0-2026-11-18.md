# 003 1.1.0（2026-11-18）

- 版本号：`1.1.0`
- 时间戳：2026-11-18 19:07（代码与文档）；测试时间见 `8.TEST/TEST.md`
- 开发人员反馈：beta 已到 0.113.1，正式版为 0.111.1；要求只兼容这两个版本并检查兼容性。发现 0.113.1 新增 `CardModel.BigPortrait`，图鉴大图会绕过原有 `Portrait` 补丁，需要新增条件补丁。
- 实装更改概括：
  - 新增 `OutbreakBigPortraitPatch`，只在 `CardModel.BigPortrait` 存在时手动应用。
  - `ModEntry` 增加属性探测与 applied/skipped 日志。
  - manifest `version` 升 `1.1.0`，`min_game_version` 升 `0.111.1`。
  - csproj 增加 `Version` / `AssemblyVersion` / `FileVersion` = `1.1.0`。
  - 文档体系重建为 `1.PRD` … `10.OUTPUT` 十目录结构，新增 PRD、SPEC、TEST 与兼容性报告。
- 简略技术细节：
  - `AbstractModel.AfterDeath` 在 0.111.1 为 4 参、0.113.1 为 5 参；现有 Prefix 只声明共有参数名，按名绑定。
  - `CreatureCmd.Damage` 5 参重载两版本都有；0.113.1 内部再转发 8 参，mod 不直接引用。
  - `CardModel.BigPortrait` 是 0.113.1 新增的非虚属性；放进 `PatchAll` 会让 0.111.1 的 `PatchAll` 因目标缺失抛异常，因此改为 `AccessTools.PropertyGetter` 探测后手动 `Harmony.Patch`。
  - `NInspectCardScreen.UpdateCardDisplay` 在 0.113.1 额外调用 `NCard.SetPortraitTexture(BigPortrait)`；现有 `SetCard` 守护调用原方法，保留该步骤。
- 失败经验或实验教训：
  - 「新增属性」和「新增方法」一样会造成跨版本补丁失败；不能因为属性只是读取就默认 `PatchAll` 安全。
  - 单 DLL 跨版本的前提是程序集未强命名；`sts2` 与 `0Harmony` 均为 `PublicKeyToken=null`，版本同为 `0.1.0.0` / `2.4.2.0`。
  - 0.113.1 的图鉴大图路径使用 `PreloadManager.Cache`，非图集纹理会被记为 missed cache asset；安全加载器仍是必要的。
- 待做/待决定：
  - 用户在 0.111.1 实机回归。
  - 0.114+ 不在承诺范围。
- 测试结果：
  - 0.113.1 无头场景：1 层尸爆让 26/27 HP 的敌人各损失 25（剩 1/2）；2 层尸爆全灭剩余敌人并结束战斗。
  - 0.111.1 留存程序集编译：0 警告 0 错误。
  - 图鉴大图 UI 与 0.111.1 实机未验证。

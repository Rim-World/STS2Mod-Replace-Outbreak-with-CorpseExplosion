- 日期：2026-08-21
- 项目：`CorpseExplosionReplacementMod`（源码 `9.SRC/CorpseExplosionReplacementMod`，成品 `C:\Game\Steam\steamapps\common\Slay the Spire 2\mods\CorpseExplosionReplacementMod`）
- 状态：**✅ 已实施并构建安装（A + B1改进版 + 版本号 1.0.0），用户游戏内验证通过（2026-08-21，v0.111.0）**。B1 实际实现为保护未被补丁过的 `NInspectCardScreen.SetCard`（复制原逻辑、原方法调用 `UpdateCardDisplay` 保留第三方补丁链、try/catch 吞异常、带仅渲染卡牌兜底），详见 `3.DOCS/001-T-图鉴大图空白根因与修复.md`。

## 一、现象

- 卡牌替换效果全部正常：费用 2、单体施毒+尸爆标记、卡面（尸爆术卡图）、打出效果均正常。
- 唯独**图鉴（Card Library）内点击 Outbreak 卡打开大图**：界面只有暗色遮罩背景，**卡牌完全看不见**；不勾选"查看升级"同样复现（用户确认）。
- 用户同系列其他替换 mod（幻影杀手/死亡收割）所替换的卡牌无此问题。
- 用户确认：v0.111.0 复现；**战斗中 buff/毒图标区域也有明显异常**（同一根因）。

### 2.2 机制链

1. **游戏 v0.111 的资源清理**：`MegaCrit.Sts2.Core.Assets.AssetCache.UnloadMissedCacheAssets()`（回主菜单/进房间时由 `PreloadManager.LoadCommonAndMainMenuAssets`/`LoadRoomAssets` 调用）会**主动 Dispose 所有"未预缓存"资源**（`_missedCacheAssets` 中记录的路径）。
2. **AssetCache 的记录规则**（`AssetCache.LoadAsset`）：经 `PreloadManager.Cache.GetXxx(path)` 加载且**不在预加载清单**中的资源会被记入 missed 并打 `Asset not cached` 警告；**`AtlasTexture` 例外（不记录、不清理）**。
3. **Godot C# 的毒化现象**：被 `Dispose()` 的 `CompressedTexture2D` 的 C# wrapper 若仍被引用（ResourceCache 路径映射、mod 静态缓存），后续 `ResourceLoader.Load(同路径, CacheMode.Reuse)` **仍返回同一个已 dispose 的 wrapper**；任何 `TextureRect.SetTexture(该 wrapper)` 抛 `ObjectDisposedException`。
4. **为什么只有尸爆术卡大图空白**：
   - 图鉴大图 `NInspectCardScreen.UpdateCardDisplay` 的最后一步必然创建卡牌 hover tips：`NHoverTipSet.CreateAndShow(cardModel2.HoverTips)` → `Init` → `SetTexture(hoverTip.Icon)`。
   - 尸爆术 mod 把 Outbreak 的 `ExtraHoverTips` 替换为自定义 **`CorpseExplosionPower`**，其 hover tip 图标 = **mod pck 内独立 png（CompressedTexture2D）** → 属于"会被 AssetCache 记录并清理"的类型。
   - 幻影杀手/死亡收割替换的卡（ShadowStep/NotYet）**未改 ExtraHoverTips**，hover tip 图标是**原版 power 的图集切片（AtlasTexture）** → `AssetCache.LoadAsset` 对 AtlasTexture 不记录、不清理 → 不毒化。
   - 因此只有自定义 power 图标的卡（尸爆术）在大图 hover tip 阶段 SetTexture 到被清理的纹理 → **异常中断 `UpdateCardDisplay` → `Open` 中断 → 卡牌停留在透明状态（上次 Close 时的 `modulate = transparentWhite`）→ 只有暗色遮罩，卡牌不可见**。
5. 战斗中 `NPower.Reload` 的 buff 图标（含毒图标等原版资源）报同一异常——同一机制（原版毒图标也在 missed 列表），界面降级但战斗流程不中断。

## 三、修复方案

### 方案 A：加载器改造（治本，已确认）

**目标**：mod 的卡图/图标纹理不再依赖 Godot `ResourceCache`/pck 资源生命周期，永不被游戏清理机制 Dispose。

**改动文件**（仅 mod 内）：
- `PortraitTextureLoader.cs`（卡图 1000×760）
- `PowerIconTextureLoader.cs`（power 图标 64/256）

**要点**：

1. **每次 Get 时校验纹理有效性**：`GodotObject.IsInstanceValid(_texture)` 为 false（被清理/毒化）时自动重建。
2. **重建优先级**：
   - ① 重新尝试 `ResourceLoader.Load(pck 路径)`（`CacheMode.Reuse`）——若 ResourceCache 已被毒化，返回的仍是失效 wrapper，`IsInstanceValid` 为 false 则继续；
   - ② 回退 **DLL 内嵌 PNG → `Image.LoadPngFromBuffer` → `ImageTexture.CreateFromImage`**。
3. **内嵌 ImageTexture 是纯运行时对象**：不进 ResourceCache、不被 AssetCache 管理、不会被游戏 Dispose——作为兜底永不失效。
4. **静态缓存策略**：pck 纹理与内嵌纹理分开缓存；pck 纹理每次 Get 做有效性检查（失效即重建），内嵌纹理创建一次后长期缓存（理论上永不失效）。
5. **保持现状的 pck 优先策略**：pck 纹理正常时（例如全新启动会话内未被清理），仍用 pck 纹理（与现版本行为一致）；仅在失效时回退内嵌，避免大图卡面与现版不一致。
6. `PowerIconTextureLoader` 的 `Get64()/Get256()` 同样处理。

**效果**：`PowerModel.Icon/BigIcon`（mod patch 后）返回的纹理始终有效 → 大图 hover tip 的 `SetTexture` 不再抛异常 → `UpdateCardDisplay` 正常完成 → 大图正常显示；战斗中尸爆标记 buff 图标同时修复。

**代码草案**（`PortraitTextureLoader`，`PowerIconTextureLoader` 同构）：

```csharp
public static class PortraitTextureLoader
{
    private static Texture2D? _pckTexture;
    private static Texture2D? _embeddedTexture;

    public static Texture2D Get()
    {
        // 1) pck 纹理仍有效则直接返回
        if (GodotObject.IsInstanceValid(_pckTexture))
        {
            return _pckTexture;
        }

        // 2) 重新尝试 pck（可能返回毒化实例；IsInstanceValid 会拦住）
        try
        {
            _pckTexture = ResourceLoader.Load<Texture2D>(ModEntry.PortraitPng);
            if (GodotObject.IsInstanceValid(_pckTexture))
            {
                return _pckTexture;
            }
            _pckTexture = null;
        }
        catch (Exception e)
        {
            Log.Warn($"{ModEntry.ModId}: pck portrait reload error: {e.Message}");
            _pckTexture = null;
        }

        // 3) 内嵌 ImageTexture 兜底（运行时纹理，永不失效）
        return GetEmbedded();
    }

    private static Texture2D GetEmbedded()
    {
        if (GodotObject.IsInstanceValid(_embeddedTexture))
        {
            return _embeddedTexture;
        }
        try
        {
            using Stream? stream = Assembly.GetExecutingAssembly()
                .GetManifestResourceStream("CorpseExplosionReplacementMod.assets.corpse_explosion_big.png");
            if (stream != null)
            {
                using var ms = new MemoryStream();
                stream.CopyTo(ms);
                var image = new Image();
                if (image.LoadPngFromBuffer(ms.ToArray()) == Error.Ok)
                {
                    _embeddedTexture = ImageTexture.CreateFromImage(image);
                }
            }
        }
        catch (Exception e)
        {
            Log.Error($"{ModEntry.ModId}: embedded portrait fallback failed: {e}");
        }
        return _embeddedTexture!;
    }
}
```

（`GodotObject.IsInstanceValid(null)` 返回 false，无需判空；静态字段的 `_pckTexture` 被毒化后下次 Get 自动重建/回退。）

### 方案 B：大图异常兜底（防御，已确认）

**目标**：即使未来再有任何 hover tip 图标纹理异常（含其他 mod/原版资源被清理），大图界面也不中断、不空白。

**推荐 B2 变体**：替换式补丁保护 `NHoverTipSet.Init`（private 方法，Harmony 可 patch）——在创建 hover tip 控件并 `SetTexture` 前，跳过 Icon 已失效的 HoverTip（Icon 置 null 后 `SetTexture(null)` 合法，仅该图标区域留空，其余全部正常）。

- 保护面广：图鉴网格悬停、图鉴大图、战斗中怪物悬停、卡牌预览 hover tips 全部受益。
- 代码量中等（复制 Init 约 55 行，含 `IHoverTip.RemoveDupes`、`PreloadManager.Cache.GetScene("res://scenes/ui/hover_tip.tscn")`、`control.ResetSize()`、`NHoverTipSet.Clear()` 等公开 API 调用）。
- **风险**：`Init` 已被其他 mod 补丁过（日志 `Init_Patch1`），替换式补丁会绕过既有补丁链；需确认该补丁来源（无法静态确认，实施前可先用 `Harmony.GetPatchedMethods`/日志观察）。若确认冲突，降级为 B1。

**备选 B1 变体**：替换式补丁保护 `NInspectCardScreen.UpdateCardDisplay`（复制约 25 行 + try/catch，异常时跳过 hover tips 创建、保留卡牌渲染）。
- 代码量小；但只保护图鉴大图，且同样有绕过 `UpdateCardDisplay_Patch1` 既有补丁链的风险（该补丁来源不明，疑似 CustomCardBalance 等）。

**兜底策略说明**：方案 A 实施后，mod 自身纹理已不可能失效，B 的价值在于防御**游戏原版纹理被清理**（如毒图标、能量图标，日志已见 `Asset not cached: res://images/powers/poison_power.png` 与能量图标路径）在大图路径上引发的同类中断。若 B 的替换式补丁与第三方 mod 冲突，可仅保留 A（A 已根治本 mod 问题）。

# 总体设计：尸爆术替换（CorpseExplosionReplacementMod）

- 文档版本：1.0（2026-11-01 从源码首次成文）
- 适用源码：`9.SRC/CorpseExplosionReplacementMod/`（v1.0.0）
- 目标游戏：Slay the Spire 2，`min_game_version` 0.110.0

本文只写源码与既有文档能够证实的内容；推导得出或无法确认的部分，分别标注「推断」与「未记录」。

## 1. 设计目标

把游戏中静默猎手的技能牌「毒性爆发」（`Outbreak`）**整卡替换**为《杀戮尖塔 1》的「尸爆术」（`Corpse Explosion`），包括费用、目标、数值、打出效果、卡名与卡面文本、卡图、Buff 图标与 Buff 动态文本。

设计约束（来自 `1.ADR/001-尸爆术替换mod立项.md` 与 mod 清单）：

1. **不新增卡牌**。直接在原 `Outbreak` 模型上改，而不是「生成新卡 + 禁用旧卡」；因此历史存档中的 `Outbreak` 会自动以尸爆术形态出现，关闭 mod 后恢复原状。
2. **最小依赖**。`dependencies` 为空，除游戏自带的 Harmony 外不引用任何基础 mod。
3. **版本门槛**。`min_game_version` 为 `0.110.0`；低于该版本由游戏侧拒绝加载（含 DLL 与 PCK）。
4. **失效安全**。若未来版本改变了 `Outbreak` 的形态，全部补丁自动失效，不得把游戏改坏。
5. **15 语言全量**。文本取自 STS1 官方本地化，仅做格式转换。

## 3. 架构与模块划分

```
CorpseExplosionReplacementMod.dll
├── ModEntry                 入口：注册 Harmony 补丁
├── ModConfig                开关：恒定跟随 OutbreakShapeGuard
├── CorpseExplosionPower     自定义 Debuff 模型（死亡触发爆炸）
├── Patches/
│   ├── OutbreakShapeGuard              形态守卫（无 Harmony 特性，供 ModConfig 调用）
│   ├── OutbreakCorePatches             目标类型 / CanonicalVars / ExtraHoverTips
│   ├── OutbreakEnergyCostPatch         费用 getter 与 CardEnergyCost.Canonical
│   ├── OutbreakOnPlayPatch             打出逻辑整体替换
│   ├── OutbreakTextPatches             卡名与卡面描述
│   ├── OutbreakPortraitPatches         卡图三个取用点
│   ├── CorpseExplosionPowerPatches     Buff 标题/描述/智能描述/图标
│   └── OutbreakInspectCardGuardPatch   图鉴大图打开流程守护
├── PortraitTextureLoader    卡图纹理：pck 优先 + DLL 内嵌兜底 + 有效性自检
└── PowerIconTextureLoader   Buff 图标（64/256）：同策略
```

模块依赖方向单一：`Patches/*` → `ModConfig` → `OutbreakShapeGuard`；纹理相关补丁 → 两个 Loader → `ModEntry` 的路径常量。`CorpseExplosionPower` 不依赖任何补丁类。

### 3.1 `ModEntry`

- 以 `[ModInitializer("ModLoaded")]` 声明入口方法 `ModLoaded()`。
- 方法体：`new Harmony(ModId).PatchAll(Assembly.GetExecutingAssembly())`，整体包在 `try/catch` 中，失败仅记 `Log.Error`，不抛出。
- 只暴露三个资源路径常量：`PortraitPng`、`PowerIcon64Path`、`PowerIcon256Path`，统一为 `res://CorpseExplosionReplacementMod/images/...`。
- **没有** `ModelDb.Inject` 调用：`CorpseExplosionPower` 依赖游戏对模组 `AbstractModel` 子类型的自动发现（ADR 记录的启动崩溃就是多余注入导致重复注册后删除的）。

### 3.2 `ModConfig`

```csharp
public static bool IsReplaceOutbreakEnabled => OutbreakShapeGuard.IsSupported();
```

即「开关」不是一个可持久化设置，而是形态校验结果。所有补丁的前缀/后缀都先读这个属性。RitsuLib 设置页在 v0.2.0 已整体移除。

### 3.3 `OutbreakShapeGuard`

用反射读取 `CardModel` 的两个 backing field，判断当前 `Outbreak` 是否仍是受支持的 beta 形态：

| 检查项 | 期望值 | 读取来源 |
|---|---|---|
| 卡牌类型 | `CardType.Skill` | 公开属性 `Type` |
| 目标类型 | `TargetType.AllEnemies` | `CardModel.<TargetType>k__BackingField` |
| 基础费用 | `3` | `CardModel.<CanonicalEnergyCost>k__BackingField` |

设计要点：

- 读 backing field 而不是读属性，避免读到自己打的 getter 补丁（否则形态判断永远成立）。
- 结果缓存在 `bool? _supported`；`ModelDb` 尚未就绪导致异常时返回 `true` 且**不写缓存**，等下次访问再评估。
- 判定为不支持时只记一次 `Log.Warn`（`_warned` 去重），随后所有补丁退化为原版行为。

### 3.4 `CorpseExplosionPower`

`PowerModel` 子类，`Type = Debuff`、`StackType = Counter`，`Amount` 表示爆炸倍率（本卡固定 1，可因重复施加叠加）。

覆写 `AfterDeath(PlayerChoiceContext, Creature, bool wasRemovalPrevented, float deathAnimLength)`：

1. `wasRemovalPrevented == true` 或 `creature != Owner` → 直接返回（复活类效果阻止死亡时不爆炸）。
2. 取 `Owner.CombatState?.HittableEnemies` 中排除自身且 `IsAlive` 的敌人；为空则返回。
3. 伤害值 `int damage = Owner.MaxHp * Amount`。
4. 对每个目标播 `NFireBurstVfx.Create(target, 0.75f)`。
5. 反射分派 `CreatureCmd.Damage` 结算：`ValueProp.Unpowered`、dealer 传 `null`、`CardModel` 与 `CardPlay` 参数均为 `null`。

`CreatureCmd.Damage` 的参数形状在 110 与 107 之间存在差异（7 参与 6 参），因此在静态构造期用 `Type.GetMethod` 分别取回两个重载：

| 分支 | 签名 | 使用条件 |
|---|---|---|
| 7 参 | `(PlayerChoiceContext, IEnumerable<Creature>, decimal, ValueProp, Creature, CardModel, CardPlay)` | 存在即优先 |
| 6 参 | 同上但无 `CardPlay` | 7 参不存在时 |

这样单个 DLL 在 107/110 上都能调用正确重载，无需条件编译或重新构建。

**dealer 必须为 `null`** 是本设计里最容易踩的坑：`CreatureCmd.Damage` 在 `dealer != null && dealer.IsDead` 时直接返回空结果，而尸爆的触发者正是刚死亡的怪物；传 `null` 与毒伤等环境伤害一致，伤害为普通伤害、可被格挡、不吃力量。

### 3.5 补丁清单与策略

| 目标 | 类型 | 时机 | 行为 |
|---|---|---|---|
| `CardModel.CanonicalEnergyCost` | Postfix | getter | `Outbreak` → 2 |
| `CardEnergyCost.Canonical` | Postfix | getter | 通过 `_card` 字段判断是 `Outbreak` → 2（兜底） |
| `CardModel.TargetType` | Postfix | getter | `Outbreak` → `TargetType.AnyEnemy` |
| `Outbreak.CanonicalVars` | Postfix | getter | 换成 `PowerVar<PoisonPower>(6)` + `PowerVar<CorpseExplosionPower>(1)` |
| `Outbreak.ExtraHoverTips` | Postfix | getter | 换成 `HoverTipFactory.FromPower<CorpseExplosionPower>()` |
| `Outbreak.OnPlay` | Prefix（返回 false） | 方法 | 整体替换为单体施毒 + 施尸爆标记 |
| `CardModel.TitleLocString` | Postfix | getter | 切到 `cards` 表 `RE_CORPSE_EXPLOSION.title` |
| `CardModel.Description` | Postfix | getter | 切到 `cards` 表 `RE_CORPSE_EXPLOSION.description` |
| `CardModel.PortraitPngPath` / `PortraitPath` | Prefix（返回 false） | getter | 指向 mod 内 STS1 卡图 |
| `CardModel.Portrait` | Prefix（返回 false） | getter | 返回 `PortraitTextureLoader.Get()` |
| `PowerModel.Title` / `Description` / `SmartDescription` | Postfix | getter | 仅 `CorpseExplosionPower`，切到 `powers` 表 `RE_CORPSE_EXPLOSION_POWER.*` |
| `PowerModel.PackedIconPath` / `ResolvedBigIconPath` | Prefix（返回 false） | getter | 指向 mod 内 64 / 256 图标 |
| `PowerModel.Icon` / `BigIcon` | Prefix（返回 false） | getter | 返回对应 Loader 纹理 |
| `NInspectCardScreen.SetCard` | Prefix（返回 false） | 私有方法 | 复刻原逻辑并加异常守护 |

费用为什么改 getter：

- 启动顺序是「先 `ModLoaded`（打补丁）→ 后 `ModelDb.Init`（构造规范实例）」，`CardModel.EnergyCost` 懒加载时读 `CanonicalEnergyCost`，因此补 getter 后规范实例与后续克隆都以 2 费创建。
- 不能对规范实例调用 `SetCustomBaseCost`：会触发 `AssertMutable` 异常；ADR 记录过由此引发的 `CanonicalModelException` 与图鉴网格连锁异常。
- `CardEnergyCost.Canonical` 的补丁是第二层保险，覆盖任何绕过 `CanonicalEnergyCost` 直接读 canonical 的路径。

`OutbreakEnergyCostPatch.ResetOutbreakCostCaches()` 仍保留：反射清空所有 `Outbreak` 实例的 `_energyCost` 字段，供开关切换后重建费用缓存。当前开关恒定（跟随形态守卫），常规流程不会触发它；它属于 RitsuLib 时代遗留的公开方法。

### 3.6 打出流程（`OutbreakOnPlayPatch`）

```
TriggerAnim(owner, "Cast", castAnimDelay)
  └─ cardPlay.Target == null ? return
  └─ NPoisonImpactVfx.Create(target)
  └─ PowerCmd.Apply<PoisonPower>(choiceContext, target, DynamicVars.Poison.BaseValue, owner, instance)
  └─ PowerCmd.Apply<CorpseExplosionPower>(choiceContext, target, DynamicVars["CorpseExplosionPower"].BaseValue, owner, instance)
```

与版本差异：原版 `Outbreak` 是对**全体**施毒并**立即触发毒**；替换后为**单体**施毒并挂尸爆标记，不再立即触发。

升级效果：本 mod **没有**替换 `Outbreak.OnUpgrade`。升级后毒 6 → 9 依赖原版升级逻辑对 `PoisonPower` 变量的加值；尸爆倍率不随升级变化（`CanonicalVars` 中第二个变量固定 1）。此路径的具体实现细节「未记录」于源码注释。

### 3.7 纹理加载与资源兜底

两个 Loader 结构一致：**pck 优先、每次自检、内嵌兜底**。

```
Get()
 ├─ IsInstanceValid(_pckTexture) ? 返回 _pckTexture          // 快速路径
 ├─ ResourceLoader.Load<Texture2D>(res://...)
 │    ├─ 有效 → 缓存并返回
 │    └─ 无效/异常 → 置空并告警
 └─ 内嵌 PNG → Image.LoadPngFromBuffer → ImageTexture.CreateFromImage
      └─ 缓存于 _embeddedTexture，永不失效
```

设计理由（详见 `3.DOCS/001-T-图鉴大图空白根因与修复.md`）：

- 游戏 v0.111 的 `AssetCache.UnloadMissedCacheAssets` 会 Dispose 未预缓存的资源，包括 mod pck 里的 `CompressedTexture2D`；被 Dispose 的 C# wrapper 仍可能被 `ResourceCache` 返回，从而在 `SetTexture` 时抛 `ObjectDisposedException`。
- 运行时创建的 `ImageTexture` 不进 `ResourceCache`，不受 `AssetCache` 管理，可长期持有。
- 内嵌资源与 pck 资源是同一张 PNG（csproj `EmbeddedResource`），视觉无差异。

`PortraitTextureLoader` 与 `PowerIconTextureLoader` 的差别仅在数量（1 张 vs 64/256 两张）与资源名，策略相同。

### 3.8 图鉴守护（`OutbreakInspectCardGuardPatch`）

替换 `NInspectCardScreen.SetCard`（私有方法），Prefix 返回 `false` 后自行完成：

1. 反射取 `_cards`、`_index`、`_leftButton`、`_rightButton`、`_upgradeTickbox`、`_viewAllUpgraded`、`_card`。
2. 复刻原逻辑：索引夹取、左右翻页按钮可见性与 `MouseFilter`、升级勾选框状态。
3. 通过反射调用**原** `UpdateCardDisplay`（保留第三方 mod 的补丁链），外层 `try/catch`。
4. 异常时降级 `TryRenderCardOnly`：`MutableClone` + `_card.Model` + `UpdateVisuals(PileType.None, CardPreviewMode.Normal)`，只渲染卡牌本体、跳过 hover tips。

选择替换 `SetCard` 而不是 `UpdateCardDisplay` 的原因：日志显示 `UpdateCardDisplay` 已被第三方补丁链覆盖（`UpdateCardDisplay_Patch1`），替换会绕过他人补丁；`SetCard` 当时未被补丁。

## 4. 数据流

```
游戏启动
  └─ 读取 CorpseExplosionReplacementMod.json → 校验 min_game_version(0.110.0) 与 has_dll/has_pck
      └─ 加载 DLL → ModInitializer 触发 ModLoaded()
          └─ Harmony.PatchAll(本程序集)

ModelDb.Init（晚于 ModLoaded）
  └─ 自动发现并构造 CorpusExplosionPower / Outbreak 规范实例
      └─ 首次读取卡牌属性时：
          CardModel.CanonicalEnergyCost → 2
          CardModel.TargetType → AnyEnemy
          Outbreak.CanonicalVars → 毒 6 + 尸爆 1
          CardModel.TitleLocString / Description → RE_* 键
          CardModel.Portrait* → PortraitTextureLoader.Get()

战斗中打出
  └─ Outbreak.OnPlay（被替换）
      └─ PowerCmd.Apply<PoisonPower>(6/9)
      └─ PowerCmd.Apply<CorpseExplosionPower>(1)

目标死亡
  └─ PowerModel.AfterDeath（CorpseExplosionPower 覆写）
      └─ 遍历 HittableEnemies（排除自身、仅存活）
      └─ VFX：NFireBurstVfx
      └─ CreatureCmd.Damage(dealer=null, ValueProp.Unpowered, damage = MaxHp × Amount)
```

## 5. 数据结构与接口

| 实体 | 形式 | 说明 |
|---|---|---|
| `CorpseExplosionPower` | `PowerModel` 子类 | `Amount` = 爆炸倍率；本地化 slug 为 `corpse_explosion_power` |
| 本地化键 | `cards` / `powers` 表 | 统一 `RE_` 前缀：`RE_CORPSE_EXPLOSION.*`、`RE_CORPSE_EXPLOSION_POWER.*` |
| 卡面变量 | `DynamicVar` | `PoisonPower`（基础 6，升级 +3）、`CorpseExplosionPower`（固定 1） |
| 卡图 | `res://CorpseExplosionReplacementMod/images/card_portraits/big/corpse_explosion.png` | 另有两份同图位于 `card_portraits/` 与 `images/...` 供不同取用点 |
| Buff 图标 | `res://…/images/powers/corpse_explosion.png`（64）、`…/images/powers/big/corpse_explosion.png`（256） | 由 Loader 保护 |
| 内嵌资源 | `CorpseExplosionReplacementMod.assets.corpse_explosion_big.png`、`…_power_64.png`、`…_power_256.png` | csproj 中显式声明 `LogicalName` |

`RE_` 前缀的由来：CustomCardBalance v2.8.0 曾与旧键名冲突，导致同系列 mod 的卡面出现重复关键词；v0.2.0 起三个 mod 统一改用前缀，等价于命名空间隔离。

## 6. 异常处理策略

| 位置 | 策略 |
|---|---|
| `ModLoaded` | 整个打补丁过程 `try/catch`，失败记 `Log.Error` 后放弃，不向上抛 |
| 纹理加载 | pck 失败 → 告警并转内嵌；内嵌也失败 → `Log.Error` 后返回 `null`（调用方需容忍空纹理） |
| 形态守卫 | `ModelDb` 未就绪 → 返回 `true` 且不缓存；反射字段缺失 → 判为不支持并告警一次 |
| 图鉴守护 | `SetCard` 外层 catch 记 `Log.Error`；`UpdateCardDisplay` 失败降级为仅渲染卡牌 |
| 费用缓存重置 | `try/catch` 后仅告警，不影响主流程 |

设计取向：**所有补丁失败都不允许把游戏带崩**，最差退化为「原版 `Outbreak` 行为」。

## 7. 兼容性设计

1. **版本门槛**：`min_game_version = 0.110.0`。107 由游戏直接拒绝加载，不进入代码路径。
2. **不检测平台分支**：v0.2.1 起移除了 `PlatformUtil.GetPlatformBranch()` 判断，只靠 manifest + 形态守卫。若未来正式版同时满足「版本号 ≥ 0.110.0」且「`Outbreak` 形态未变」，mod 会自动生效。
3. **形态守卫**：`Outbreak` 形状变化即整体退化为原版，不会把图鉴改坏。
4. **重载适配**：`CreatureCmd.Damage` 用反射选重载，跨 107/110 通用。
5. **命名空间隔离**：本地化键 `RE_` 前缀；Harmony 实例以 `ModId` 命名。
6. **与他 mod 共存**：替换 `NInspectCardScreen.SetCard` 时保留原 `UpdateCardDisplay` 的补丁链；不改任何全局设置。
7. **已知不保证**：盗版、修改版、移动版、老旧版本、冷门/次级 mod 的兼容性未验证，整理时亦未做兼容性回归。

## 8. 构建与测试

### 8.1 构建

`9.SRC/CorpseExplosionReplacementMod/build.ps1`：

1. `dotnet build CorpseExplosionReplacementMod.csproj -c Debug`；
2. 定位 `.godot/mono/temp/bin/Debug/CorpseExplosionReplacementMod.dll`（与 `.pdb`）；
3. `Godot --headless --import --path <源码根>`；
4. `Godot --headless --export-pack "Windows Desktop" <mods>/CorpseExplosionReplacementMod.pck --path <源码根>`；
5. 把 DLL/PDB/JSON 复制到 `C:\Game\Steam\steamapps\common\Slay the Spire 2\mods\CorpseExplosionReplacementMod\`。

脚本内的游戏根目录、Godot 可执行文件路径均为本机绝对路径（`C:\Game\Steam\...`、`C:\Godot&GDRE\...`），换机需自行修改。构建输出目录不是仓库内的 `bin/`，而是 `.godot/mono/temp/bin/Debug/`。

### 8.2 测试

仓库内**没有**自动化测试工程或脚本，`未记录` 单元测试与 E2E 测试设施。既有验证方式均为「构建安装 + 游戏内人工回归」，检查项与结论记录在：

- `2.PLANS/PLANS.md` 的施工记录回填表；
- `2.PLANS/002-S-图鉴大图空白修复.md` 第五节的验证清单；
- `3.DOCS/001-T-图鉴大图空白根因与修复.md` 的验证结论。

人工回归覆盖：图鉴大图（含翻页/升级视图）、图鉴网格悬停、战斗中 buff 图标、主菜单往返后复测、其他替换 mod 的卡牌大图、日志中是否仍有 `ObjectDisposedException`。
